    campus app¶

    Hosted-app publishing commands (campus.api)

    campus app delete¶

    Delete a hosted app by slug.

    campus app delete [OPTIONS]

    Arguments/options:

    • --slug, text, required — App slug.
    • --confirm/-y — Skip confirmation.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus app get-content¶

    Fetch a hosted app's raw HTML (to stdout or --output path).

    campus app get-content [OPTIONS]

    Arguments/options:

    • --slug, text, required — App slug.
    • --output/-o, path — Write the bytes to this path.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus app get-meta¶

    Show a hosted app's metadata.

    campus app get-meta [OPTIONS]

    Arguments/options:

    • --slug, text, required — App slug.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus app list¶

    List hosted apps (optionally by slug prefix).

    campus app list [OPTIONS]

    Arguments/options:

    • --prefix, text — Only slugs starting with this prefix.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus app put¶

    Publish or replace a hosted app by slug (upsert).

    campus app put [OPTIONS]

    Arguments/options:

    • --slug, text, required — App slug (stable address).
    • --file/-f, path, required — Local single-file HTML app to publish.
    • --content-type, text — MIME type (defaults to text/html upstream).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    Audit API key lifecycle (operator)

    campus audit keys get¶

    Show one audit API key's record (never its plaintext).

    campus audit keys get [OPTIONS]

    Arguments/options:

    • --key-id, text, required — API key ID (from keys list).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit keys list¶

    List audit API keys, optionally filtered by owner. Requires apikeys:read on the stored key (the operator key).

    campus audit keys list [OPTIONS]

    Arguments/options:

    • --owner, text — Filter by owner.
    • --all — Include revoked and expired keys (default: active only).
    • --limit, integer — Page size.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit keys new¶

    Create an audit API key (mint a student key). Give the key a privilege: --role for one of the service's named roles (a bundle of scopes it owns), or --scope for a hand-assembled scope list. The two are mutually exclusive — the server refuses both together, because it leaves it ambiguous which was meant. Scoping (#944): a key granting trace reads without traces:write/ apikeys:write must be minted with a bind — pass --trace-user-id (usually the student's id) and/or --trace-client-id; the server refuses the mint with 422 otherwise. The bind is an opaque match-value enforced server-side on every read surface and cannot be changed after minting. The plaintext key is shown exactly once, at creation — the server keeps only its hash. Pass it to the student; they store it with 'campus audit login --api-key'.

    campus audit keys new [OPTIONS]

    Arguments/options:

    • --name, text, required — Key name, e.g. the student's name.
    • --owner, text, required — Owner label, conventionally the student email (organizational only — campus.audit is user-blind).
    • --scope, text — Scope the key grants, e.g. traces:read; repeat for multiple (mutually exclusive with --role).
    • --role, text — Named role the key gets, e.g. traces-viewer. The role is a bundle of scopes the service owns; --scope and --role are mutually exclusive.
    • --rate-limit, integer — Requests per minute (optional).
    • --expires-at, text — ISO 8601 expiry (optional).
    • --trace-user-id, text — Bind trace reads to this user exactly (#944; required for read-scoped keys unless the key holds traces:write/apikeys:write).
    • --trace-client-id, text — Bind trace reads to this client exactly (#944).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit keys regenerate¶

    Replace an audit API key's plaintext value (rotation). The old value stops working immediately; the new one is shown exactly once here. Scopes, rate limit, and expiry carry over.

    campus audit keys regenerate [OPTIONS]

    Arguments/options:

    • --key-id, text, required — API key ID (from keys list).
    • --confirm/-y — Skip confirmation.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit keys revoke¶

    Revoke an audit API key (the record is kept for audit). The key stops authenticating immediately; its record stays listed under --all for the audit trail.

    campus audit keys revoke [OPTIONS]

    Arguments/options:

    • --key-id, text, required — API key ID (from keys list).
    • --confirm/-y — Skip confirmation.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit keys update¶

    Update an audit API key's name, scopes, role, or rate limit. Only the fields passed are changed. Expiry and revocation are immutable — mint a fresh key instead. --role and --scope are mutually exclusive: the server refuses both together, because it leaves it ambiguous which was meant.

    campus audit keys update [OPTIONS]

    Arguments/options:

    • --key-id, text, required — API key ID (from keys list).
    • --name, text — New key name.
    • --scope, text — Replacement scope set; repeat for multiple. Omit to keep the current scopes (mutually exclusive with --role).
    • --role, text — Named role the key gets, e.g. traces-viewer. The role is a bundle of scopes the service owns; --scope and --role are mutually exclusive.
    • --rate-limit, integer — Requests per minute.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit login¶

    Store an API key for the campus.audit service (#54). Unlike OAuth tokens, audit keys never expire server-side into a refresh flow: a revoked or deleted key is cleared by re-running this command with a new one. The key is stored in the shared credential store, bound to the audit URL the CLI currently targets.

    campus audit login [OPTIONS]

    Arguments/options:

    • --api-key, text — The audit API key (audit_v1_...). Falls back to the CAMPUS_AUDIT_API_KEY environment variable, then an interactive prompt..
    • --skip-verify — Store the key without checking it against the service.

    campus audit logout¶

    Clear the stored audit API key (local only). This does not disable the key server-side — audit keys cannot revoke themselves. To invalidate a key, revoke it first: 'campus audit keys revoke --key-id '.

    campus audit logout [OPTIONS]

    Arguments/options:

    • --confirm/-y — Skip confirmation prompt.

    campus audit status¶

    Show the stored audit key's local state (#62). The audit service has no "who am I" endpoint, so this is a purely local view: whether a key is stored, which URL it is bound to, the URL the CLI currently targets (flagging a mismatch the way the commands' guard does), and when the key was stored. No network call is made — unlike 'campus auth status', there is no online check. Exit code: 1 when no key is stored, 0 otherwise (a bound/target mismatch is reported but does not fail the check; every API-backed command refuses on its own until re-login).

    campus audit status [OPTIONS]

    Arguments/options:

    • --json — Output status as JSON.

    campus audit traces¶

    Trace queries (read-only)

    campus audit traces get¶

    Show a trace's detail: root-span essentials (origin, UA, size) plus its child spans. Use --json for the raw span tree. The tree is the trace: the root span with its children nested, each span carrying the recorded request/response detail.

    campus audit traces get [OPTIONS]

    Arguments/options:

    • --trace-id, text, required — 32-char hex trace ID.
    • --json — Raw span tree as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit traces list¶

    List recent traces, newest first.

    campus audit traces list [OPTIONS]

    Arguments/options:

    • --since, text — ISO 8601 lower bound on trace time.
    • --until, text — ISO 8601 upper bound on trace time.
    • --limit, integer — Page size.
    • --cursor, text — Opaque token from a previous page.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus audit traces search¶

    Search traces by journey, endpoint, outcome, principal, or time. Filters combine (AND).

    campus audit traces search [OPTIONS]

    Arguments/options:

    • --path, text — Filter by endpoint path.
    • --status, integer — Filter by HTTP status code.
    • --user, text — Filter by user ID.
    • --client, text — Filter by OAuth client ID.
    • --api-key-id, text — Filter by audit API key ID.
    • --journey, text — Filter by login-journey ID.
    • --since, text — ISO 8601 lower bound on trace time.
    • --until, text — ISO 8601 upper bound on trace time.
    • --limit, integer — Page size.
    • --cursor, text — Opaque token from a previous page.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus auth¶

    Authentication commands

    campus auth login¶

    Authenticate with Campus API using Device Authorization Flow. This will: 1. Request a device code from the server 2. Display a code for you to enter at the verification URL 3. Poll for the token while you complete authentication in a browser 4. Store the received token in your credential manager The auth endpoint is resolved from the CAMPUS_AUTH_URL environment variable, the config file, or ENV/CAMPUS_ENV (see campus_cli.config).

    campus auth login [OPTIONS]

    Arguments/options:

    • --output-token/-t — Output the access token to stdout.
    • --scope/-s, text, default: [] — Request a management scope for the token (#865); repeat for multiple (e.g. --scope clients:write). The server rejects scopes outside this client's registered allowlist — an operator must widen it first..

    campus auth logout¶

    Log out and clear stored credentials. Removes the stored access and refresh tokens from the credential store, after attempting server-side revocation (RFC 7009). Revocation is best-effort: logout still succeeds when the server is unreachable or deployed without a revocation endpoint. Logging out while not authenticated is a no-op reported as success.

    campus auth logout [OPTIONS]

    Arguments/options:

    • --confirm/-y — Skip confirmation prompt.

    campus auth refresh¶

    Refresh the access token using the stored refresh token. Manually refresh your access token. This is also done automatically when running commands (if auto_refresh is enabled).

    campus auth refresh [OPTIONS]

    Arguments/options:

    • --output-token/-t — Output the new access token to stdout.
    • --json — Output status as JSON.

    campus auth status¶

    Show the stored credential's identity and scopes (#45). Prints the auth client id, the endpoint in use (and the endpoint that minted the token), the authenticated principal, the scopes the stored token carries, and token expiry — everything scripts need to answer "what can this token do?" before acting. Unless --offline is given, a lightweight authenticated check also reports whether the token still authenticates (network errors are non-fatal: they are reported without failing the command). Exit code: 1 when not logged in, or when the stored token is rejected by the server; 0 otherwise.

    campus auth status [OPTIONS]

    Arguments/options:

    • --json — Output status as JSON.
    • --offline — Skip the authenticated validity check (no network calls; the check verifies the stored token against GET users/, where FORBIDDEN means valid and UNAUTHORIZED invalid). Exit codes: 0 when a stored token is present and valid — or its check was skipped, unreachable, or inconclusive; 1 when not logged in or the token was rejected by the server..

    campus client¶

    campus client access¶

    OAuth client access management commands

    campus client access get¶

    Get client vault access permissions. Displays the access permissions for a client. If --vault is specified, shows only that vault's permissions. Otherwise, shows all vault permissions.

    campus client access get [OPTIONS]

    Arguments/options:

    • --client-id/-i, text, required — Client ID.
    • --vault/-v, text — Vault label (if not specified, shows all).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus client access grant¶

    Grant vault access to a client. Grants the specified permission level for a vault to the client. Permissions are bitflags: 1=READ, 2=CREATE, 4=UPDATE, 8=DELETE. Combine with bitwise OR: e.g., 3 for READ+CREATE.

    campus client access grant [OPTIONS]

    Arguments/options:

    • --client-id/-i, text, required — Client ID.
    • --vault/-v, text, required — Vault label.
    • --permission/-p, integer, required — Permission bitflag (1=READ, 2=CREATE, 4=UPDATE, 8=DELETE).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus client access revoke¶

    Revoke vault access from a client. Revokes the specified permission level for a vault from the client. Permissions are bitflags: 1=READ, 2=CREATE, 4=UPDATE, 8=DELETE.

    campus client access revoke [OPTIONS]

    Arguments/options:

    • --client-id/-i, text, required — Client ID.
    • --vault/-v, text, required — Vault label.
    • --permission/-p, integer, required — Permission bitflag to revoke.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus client access update¶

    Update (replace) vault access for a client. Sets the permission level for a vault to the exact value specified. Use 0 to remove all access to the vault. Permissions are bitflags: 1=READ, 2=CREATE, 4=UPDATE, 8=DELETE.

    campus client access update [OPTIONS]

    Arguments/options:

    • --client-id/-i, text, required — Client ID.
    • --vault/-v, text, required — Vault label.
    • --permission/-p, integer, required — Permission bitflag to set.
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus client delete¶

    campus client delete [OPTIONS]

    Arguments/options:

    • --confirm/-y — Skip confirmation.

    campus client get¶

    Get details of an OAuth client. Retrieves and displays information about the specified client. Note: The client secret is NOT displayed.

    campus client get [OPTIONS]

    Arguments/options:

    campus client new¶

    Create a new OAuth client. Creates a new OAuth client with the specified name and description. By default the client is confidential: the client secret is NOT returned; use 'campus client revoke' to generate and retrieve it. Public clients (--public) have no client secret at all. --allowed-scope / --upstream-scope / --token-bridge set the fail-closed privilege fields at registration (the same fields 'campus client update' manages post-hoc). Scope caps and the token-bridge flag stay operator/root-only (campus#883 — clients grant rows cap at write). Authority: operator or super-admin root — client registration is not grantable through the access-grant store (campus#883).

    campus client new [OPTIONS]

    Arguments/options:

    • --name/-n, text, required — Client name.
    • --description/-d, text, required — Client description.
    • --public — Create a public client (no client secret, per RFC 6749 §2.1).
    • --redirect-uri, text, default: [] — OAuth redirect URI for the client (repeat for multiple; typically used with --public).
    • --allowed-scope, text, default: [] — Scope this client may be granted on campus tokens (repeat for multiple). Fail-closed: an empty allowlist grants nothing.
    • --upstream-scope, text, default: [] — Upstream scope as provider=scope (repeat for multiple; scopes of the same provider are grouped).
    • --token-bridge/--no-token-bridge — Grant broker token-bridge access (confidential clients only; the server rejects it for public clients).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.

    campus client update¶

    Update an OAuth client. Updates the name, description, redirect URIs, scope allowlists and/or token-bridge access of an existing client. List-valued options (--redirect-uri, --allowed-scope, --upstream-scope) REPLACE the whole stored value: the API layer full-replaces each provided field, so re-pass every entry the client must keep. Fields you omit are left untouched. Authority: your own client's profile fields are self-service; other clients need clients:write authority (grant row plus scope); the scope caps and token-bridge flag stay operator/root-only (campus#883 — clients grant rows cap at write).

    campus client update [OPTIONS]

    Arguments/options:

    • --client-id/-i, text, required — Client ID.
    • --name/-n, text — New client name.
    • --description/-d, text — New client description.
    • --redirect-uri, text, default: [] — OAuth redirect URI (repeat for multiple; REPLACES the existing list, so re-pass the full list when adding one).
    • --allowed-scope, text, default: [] — Scope this client may be granted on campus tokens (repeat for multiple; REPLACES the whole allowlist, so re-pass every scope the client must keep). Fail-closed: an empty allowlist grants nothing.
    • --clear-allowed-scopes — Empty the scope allowlist (fail-closed: grants nothing).
    • --upstream-scope, text, default: [] — Upstream scope as provider=scope (repeat for multiple; scopes of the same provider are grouped; REPLACES the whole upstream scope map, so re-pass every provider=scope pair the client must keep).
    • --token-bridge/--no-token-bridge — Grant/revoke broker token-bridge access (confidential clients only; the server rejects it for public clients).
    • --json — Output as JSON.
    • --dry-run — Show the equivalent Python API code without calling the API.
